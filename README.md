## 本リポジトリについて

本リポジトリは、Feature-Sliced Design（FSD）を採用した React アプリケーションのテンプレートである。  
UI ライブラリには Material UI、フォーム管理には React Hook Form、バリデーションには Zod を採用していいる。  
FSDについてと開発規約については[このリンク](https://github.com/MachinoTakumi52/react-fsd-template/tree/main/react-fsd-template#%E3%83%95%E3%83%AD%E3%83%B3%E3%83%88%E3%82%A8%E3%83%B3%E3%83%89%E9%96%8B%E7%99%BA%E8%A6%8F%E7%B4%84)を参照

## エージェントを使った開発の流れ

1. [指示テンプレート](TASK_TEMPLATE.md)に沿って Codex に依頼する。Codex は [AGENTS.md](AGENTS.md) に沿って実装・検証する。
2. 実装と検証が完了したら、Codex が作成したドラフト PR の差分と検証結果を確認し、マージする。
3. 検証を続けられない場合は、Codex が起票した Issue を GitHub の通知やチャットで共有されたリンクから確認する。

### ブランチ運用

- 開発の起点ブランチは `main`。
- PR のマージ先は `main`。
- テンプレートから作ったプロジェクトでブランチ運用を変える場合は、この節と [Quality Check の対象ブランチ](.github/workflows/lint.yml) を更新する。

## 開発の流れ

### コンテナを立ち上げる

vscode でプロジェクトを開く。
`コンテナで再度開く`を選択してコンテナを立ち上げる。
vscode 左下をクリックしたら出てくる。

または、docker ファイルが存在するディレクトリを vscode で開いた時、右下に`コンテナで開く`が出てくるので選択して
コンテナを立ち上げる。

以下ファイルよりコンテナ名を指定可能。

```bash
.devcontainer/docker/.env
```

### 対象プロジェクトへ移動

下記コマンドで対象プロジェクトへ移動する。
プロジェクトのフォルダ名は任意。

```bash
cd プロジェクトフォルダ名
```

### ライブラリのインストール

下記のコマンドを打つことで、ライブラリをインストールすることができる。

```bash
npm ci
```

インストールコマンドではない理由は以下。

CI(github actions)で`package-lock.json`を使用するため、git管理している。
インストールコマンドをしてしまうと、`package-lock.json`が更新される可能性があるため。

### デバッグ(ホットリロード有効)

デバッグコマンドは以下に記載。  
ホットリロードにより変更保存後、自動で更新される。  
デバックポイントは、検索エンジンの検証機能から  
コンポーネントの変更は、たまに聞かない時があるのでその時は、`ctr + r`で更新をコンポーネントの新規追加時、別画面でインポートする際に見つからないことがあるので、コマンドパレットから「Reload windows」。

```bash
npm run dev
```

### デプロイ

下記コマンドでビルド。  
`dist`フォルダにファイルが生成されるためこれをプラットフォームに配置。

```bash
npm run build
```
